# 同一份世界数据驱动总图与三维

来源：[Architecture Studio官方案例](https://developers.openai.com/showcase/architecture-studio)使用同一份文档驱动2D平面和3D视图。以下是Pawborough的工程适配设计，尚未证明本项目已经实现编辑器。

## 不再各存一份可变布局

PROJECT只负责项目入口和路径，不复制整张地图。选定一份版本化实例/布局数据作为权威，2D总图、Three场景、碰撞生成与导出由适配器消费它。现有instances.json可逐步扩展，不必另造同义的world-state系统。

每个实体至少有稳定id、assetId、区域/地块id、明确米制的position/rotation/scale、材料集引用，以及参考/推定/设计状态。几何坐标来自这份数据，不能在React状态、Blender脚本和Rapier里各改一次。

- 总图经纬度到项目坐标只转换一次，保留原资料坐标与映射依据。2D平面坐标如何映射到GLB X/Z写进同一适配器，不能用“看着差不多”的反号补丁。
- 3D选择与2D选择通过稳定id关联；改变显示方式不重建另一套逻辑实体。
- 若已有移动/旋转编辑需求，用一次更新同时派生视图与碰撞；先验证旧实例更新正确，不为了借鉴案例新造完整GUI编辑器。
- replacesBaseIds同时控制占位的渲染、碰撞与加载所有权。精修件未ready时保留占位；切换时不能出现两套墙体或碰撞缺口。卸载后按同一数据恢复，不能靠每个视图各自猜测。
- 异步导出/加载带布局版本；较旧版本结果不能覆盖刚更新的数据。场景可编辑源、运行数据和导出包的版本绑定明确。

## N6两区块最小验证

选择已有一栋斜置建筑和一个精修替换点作为样本。先用当前权威数据生成2D/3D/碰撞记录，验证id、中心、朝向和门洞对应。再只改一次样本变换，确认三处都更新；撤回改动后回到原状态。不要把修改测试写进冻结原图。

在两个区块进入/退出及晚到加载场景中，检查同id只有一套有效渲染/碰撞；精修替换失败时占位保持可用，成功后不再叠加。保存初始布局哈希、变更、导出布局哈希与实际浏览器观察，离线测试不冒充行走。

370个占位的数量并不证明历史复刻准确。素材出处和未测绘的尺寸仍标推定/设计；该方法只改数据一致性，不替代主控的区域设计与年代考据。
