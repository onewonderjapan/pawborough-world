# 可执行构造方法

## 1. 图片不是顶点坐标

建立 `measurements.json`：每个视图有宽高、地面 y、耳尖 y、头框、眼心、鼻尖、下巴、肩、胯、爪心，以及 ± 像素不确定度。坐标 `(u,v)` 从左上角计算。`height_px = floor_v-ear_v`，比例 = 像素距离/height_px。使用颅顶到下巴描述头本体，另记录耳长，避免用耳尖混淆头身比。

侧视图用于前后长度，正视图用于宽度。二维关节被毛遮挡时只记录估计区间，不把外轮廓当骨心。肩胛和髋不能由脚心向上画直线硬猜。参考图左右不一致时，先建立对称中性身体；个性姿态留到动画。

建议模型坐标为 Blender Z 向上、-Y 向前、左右为 ±X，原点在四脚支撑区域中部，单位米。实际体高可由任务指定；当前 A 是 0.32 m 的展示尺度，不代表真实猫标准身高。导出 GLB 自动换到 Y-up，别重复转轴。

## 2. 底模拟合的写法

先保留原 `.blend/.glb`，从副本开始；进入 REST，清除副本旧动作。基于中性网格坐标操作，而不是已经播放中的 evaluated mesh。区分 body 的 matrix_world 和局部 co；不要对同一变换应用两次。

将参数分成：头宽/高/深、颊宽、口鼻前伸、耳长与张角、颈长、肩胯间距、胸腹宽高、上肢/下肢长度、脚掌长宽、尾根与尾曲线。

以连续区域权重做变形，而不是 `if y<0` 把头和身切开。例如：

```python
def smoothstep01(t):
    t = max(0.0, min(1.0, t))
    return t*t*(3.0-2.0*t)

# head_center 和过渡区域从该猫测量；不是固定世界坐标口诀。
# p_head = center + scale_matrix @ (p-center) + head_translation
# p_result = p + head_weight(p) * (p_head-p)
```

颈部权重宽一些，避免断崖。脸上的眼睛、鼻、口鼻和胡须随同一头部坐标场变形；若网格独立，也要应用同样映射。改腿长需要保留地面锚点，胸廓随之上移；不要只把小腿沿 Z 拉伸造成跗部翻折。

实作中需检查的三个选区问题：
- **缩头**：头脸表面主体应有一致的缩放，软过渡集中在颈部。不要把“距头中心的椭球距离”直接当整个头的 falloff；这种写法会让眼鼻先缩而外颊、耳后留在原处。生成选区后看它是否覆盖了完整头面。
- **加长腿**：肩处增量为零、仅腿中下段增量非零，不会把身体抬高。可以用从脚掌顶到肩胯单调增加、至躯干保持恒定增量的高度映射作为静态试验起点；是否保住正常折线仍需看图。测输出的肩胯高度与腿轮廓，不能只抄参数里的倍率。
- **收腹**：`z < 腹部高度` 同时包含脚。腹部选区必须明确排除腿和爪，逐爪看接触面，不能只确认全模型最低点为零。

C 相对 A 的图片方向：头占全身比例更小，肩胯间距更长，四肢更修长，胸腹不贴地；它仍有圆脸、轻柔颊部和可爱表情。**具体数值从图片计算，不把“头缩到 0.8”当普遍规则。** 底模已有纹理可先继承来隔离形体变量，报告继承关系。大幅拉伸后的毛纹伸缩也要看。

若用骨架保持区域身份，按骨名/权重找区域再核对可见坐标。原模型实际左右可能与名字不一致。形变后更新中性骨架和 inverse bind，或第一轮只导静态模型，不能继续输出错位的旧蒙皮。

## 3. 独立网格：连续截面先于球体拼接

上次失败图见当前试验包。它用许多椭球/小球连成腿再 voxel remesh，平滑 100 次仍有玩具拼块感。重复同一构造再提高 subdivision 不构成新路线。

可实行的替代是连续截面 loft：

- 躯干沿 Y 设胸前、肩、胸最宽、腰、骨盆、臀后等截面。每截面记横向半径、中心 Z、背高与腹低；背腹分别用平滑曲线控制，不沿整个身子使用同一个椭圆。
- 连接相同顺序的环，形成四边面；颈根自然收窄后上升进入头部。不要把一只完整胸球贴在另一只完整肩球上。
- 头沿 Z 或前后 Y 建截面：颅顶、眉弓、眼心、颊、口鼻、下巴。额头后圆前缓；颊部在眼下外展，下巴收回。前半截面允许眼眶凹陷和口鼻局部前伸，后半保留颅骨圆面，不能整层同量鼓起。
- 前肢沿肩—肘—腕—掌建立弯曲中心线，截面由上粗下细再到脚掌扁宽。后肢沿髋—膝—跗—掌，先有大腿体积，再有较细的小腿和跗部。曲线切线作为截面法向，避免所有环都水平造成折点挤瘪。
- 连接肩和腿、臀和腿时用局部桥接/删交叠面后的融合；若采用体素融合，先用合理体块和连续曲线，保留融合前控制网格并对融合后形体重校。是否四边面另报，不假称动画拓扑。
- 耳朵是有厚度、外缘圆钝且内侧凹下的耳壳，耳根埋入头面，不能是一片正反同形三角板。
- 尾从骨盆背后接出，根部粗而连续变细，用平滑中心线和截面，不串出一串珠子。

这是一条待验证的构造策略，不能把教程描述写成已达到老师质量。必须以实际多视图决定哪里修正。

## 4. 眼睛与口鼻

之前的外贴完整蓝球造成呆和惊吓感。眼眶需要包住眼球的大部分，只露被上下睑限定的前部。

独立路线可做：在连续头表面沿眼框范围轻凹，生成贴脸的上下睑环；小球球心放入颅骨，露出角膜帽。镜头侧视时检查它没有像镜片悬在脸外。眼圈有厚度但不做成黑色粗眼镜框。

虹膜、瞳孔与角膜分层：虹膜为略凹/近似平面盘，瞳孔嵌入其中心，角膜仅透明薄帽；GLB 折射若不能稳定展示，使用单层有光泽的前表面作为明确兜底。避免一张画有强高光的基础色再叠多个亮白几何点。

口鼻是从脸连续前出的两个柔和须垫，下方很小的下巴向颈部收；鼻子小，嘴线浅，侧视不出现额外悬挂肉球。胡须和短毛在大形稳定后再加。

## 5. 毛色、UV 与灯光

老师资产的实际对照说明：无光基础色中仍有大量毛流与眼睛高光。因此不能只复制 roughness 值就期待同样画面。

先建立低频色区（奶油金背头、奶白口鼻胸脚、轻粉耳鼻），再沿形体方向加入低对比细毛纹。头毛从鼻梁向额头/颊部流，胸毛顺下，腿毛顺长轴，不能全身各向同性随机噪点。使用 vertex color 可以验证色区，但不能声称与 4K 毛流图等效。

独立路线可从批准图片采样颜色或做相机投影纹理，但必须有真实三维曲面；不能贴一个正脸平面冒充模型。多图投影需明确相机、面朝向和遮挡，背面不能复制正面眼睛。图像内已画入的阴影/高光要在报告注明。更可控的是依据照片色区重新程序绘制 UV 纹理；不要导入老师 UV/贴图后宣称独立材质重建。

Blender 程序节点不一定能导出。按实际格式烘焙 BaseColor / Roughness / Normal，明确图像色彩空间，导出的 GLB 再加载验证。毛身 metallic=0；roughness 0.7–0.9、微弱 sheen 可作起点，但要看具体灯光和引擎支持，不是配方答案。眼的光泽与身体分开。

固定面积光和中性环境、同一曝光，先看真实导出模型。不要为了像参考图把所有高光压没，也不要用强 bloom 掩盖网格。

Blender 批处理使用 `--python-exit-code 1`。默认行为可能在 Python traceback 后仍返回 shell 退出码 0，必须同时核对输出。比较变形时，GLB 往返可能改变顶点编号；未验证对应关系，不能逐索引相减后称为位移。空间区域统计只是近似，不是骨长或美术分数。

## 6. 能学与不能推断的边界

可由本批成品实测：形体比例、局部曲率、UV/材质组织、骨链覆盖、足端轨迹、导出后的变形。

不能据此推出：Tripo 商业 v3.1 的权重、隐式几何场、训练样本和精确生成步骤。公开 TripoSG 是图像条件的生成模型研究，不等于 Python 手工雕刻流程，也不应直接等同商业服务。
