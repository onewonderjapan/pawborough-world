# 精致静态建筑：直接低模

目标是在街边、近墙与全段观察时精致，构件和材质可复用、加载可测。机主当前优先复刻3D世界，兼作后期视频场景；角色建模和动画不作为场景施工前置。默认直接制作低模；高模/雕刻/付费生成不是前置步骤。Tripo 等现成候选可作外观参考，不自动调用服务。

## 当前入口

先读 [项目入口与范围](references/project-entry.md)，按PROJECT.json解析当前工作仓、路线图、端口和资产。以下引用里的绝对路径与数据是历史验证证据，不是默认施工目标。世界版优先，角色G1暂缓，W2一次Unity导入验证不设为前置。

## 本项目施工分工

机主指定的规则：主控负责设计、方法论Skill、有限工单与实际审查；生产建模、代码、材质和导出由ZCode施工。主控可编写派工／验证工具与设计图，不代写生产资产。当前由机主手动调用ZCode，按EXECUTION_POLICY连续推进；没有工时、截止或执行段数上限，不从历史夜班恢复时间限制。此规则不自动授权其他付费生成、跨夜续跑或定期任务。

## 先确定这一个建筑

先确定区域、年代和建筑类型，再选造型与颜色。目标是老城隍庙、豫园及附近街道时，读取 [城隍庙片区参照](references/chenghuangmiao-area.md)；旧灰砖街屋只复用技术流程，不作该片区的统一形制模板。

记录输入照片/模型、风格、宽深高、门是否开放、可见侧背面、输出目录和目标引擎。已有要求足够就直接施工。照片提供造型/材料依据；未测绘的尺寸标记为设计值。上海材料语言见 [材料与尺度](references/materials-and-scale.md)。

试验起点：普通街屋约3,000–12,000 tris，地标可约15,000–50,000；共享材质以1K/2K试验。区间下沿不是最低面数要求；这是可调整的预算，不是性能保证。预算紧时先简化重复小装饰，保留关键轮廓与开口。

## 把细节分给正确的载体

| 层次 | 建造方式 | 验证 |
|---|---|---|
| 体块/通道 | 低面数墙、真实门窗洞、坡屋顶；窗后退 | 灰模、侧面与开口检查 |
| 中等细节 | 门套退台、窗扇、窗台、檐口、细雨棚、少量倒角；花饰用简化曲面体积 | 普通视距能读到进深和边缘高光 |
| 表面细节 | 砖缝、颗粒、漆面变化用一致UV的底色/法线/粗糙度 | 同光照的纯色与完整材质对比 |

不逐砖堆盒、不逐瓦铺高密度网格。影子和法线不能替代通行门洞、外轮廓或实心门窗遮挡。关闭的建筑不造看不见的室内；浏览或取景可见的背面/屋顶不能随意省略。观察到的微小砖缝误差可接受，破洞、大片拉伸、窗框浮空和实心盒堵入口不可接受。

## 建模与材质契约

- 建筑按米建造。默认GLB为Y向上、立面朝+Z、深度向-Z、前墙中心底部为原点；场地另有契约则遵循场地。轴向在源文件修正，不靠预览页秘密旋转。
- Blender本身为Z向上：设计GLB坐标`(x,y,z)`转换为Blender`(x,-z,y)`后，才使用`export_yup=True`。若选择其他明确的内部坐标约定，应写出等价转换；预览页不补隐藏旋转。导回Blender会逆转坐标，不能用Blender坐标数字直接证明GLB坐标正确。
- 硬表面倒角需要连通的几何边；方块可用8个共享顶点，UV仍存于每面loop。六面各自4个不连接的顶点可能使ANGLE倒角无效。可在Blender中导入`scripts/blender_building_helpers.py`，使用`box_glb(name, center, size, material, tile_m, bevel)`；它明确转换坐标并保留loop UV。
- 使用本地Blender或等价DCC直接编辑最终网格。只在可见轮廓/边缘布必要倒角。屋面做连续坡面，檐边/屋脊用有限重复构件。
- 几何、碰撞代理和安装锚点分别交付。开门时碰撞至少拆两侧与门楣；闭门可封闭碰撞。明确碰撞尺寸轴向，不用渲染高细节网格承担全部物理。
- 共享墙砖、灰泥/水刷石、漆面、屋瓦材质。几何UV按表面局部米尺度展开，几段墙面接缝保持同一原点/方向，避免每块各自0–1拉伸。横竖木纹按构件方向处理。
- Color为sRGB，Normal/Roughness/Metallic/AO为数据；OpenGL切线法线。使用的贴图须能沿标准glTF PBR连接导出；过程节点需要实际烘成图或明确简化。AO不是已烘焙全局光照。
- 色彩/法线/粗糙度来自同一套纹理与UV。标准材质不要额外叠未知`vertexColor`乘色。只对需要法线图的图元导出有效切线；校验警告须读原因，不以移除警告代替看图。
- 重复放置时clone共享geometry/material/texture，记清资源所有者；卸载实例不销毁共享资源。按栋/小块组织，避免整城合成一个不可细分剔除的大网格。

## 官方工作流的适配

整理或压缩GLB、制作砖瓦木石材质对照模式时，读 [官方资产流程与材质诊断](references/official-workflows.md)。先以一个已有样板区分无损整理、几何压缩和纹理压缩的收益；固定灯光与几何后调整材料。Modeling Studio仅列可选导出探针，不作为本项目已验证的替代建模路线。

## 导出后才算得到资产

修改门洞、相机预设、导出或交付脚本时，读取 [已验证的门洞与交付方法](references/verified-delivery.md)。它区分几何、运行时和负例检查，避免用格式PASS或进程exit0替代完成。

保存`build.py`或等价制作脚本、`.blend`、`model.glb`、`collision.json`、`materials.json`。在JSON记录：模型轴向/设计尺寸、表面材料来源、纹理尺寸及每tile米数、碰撞和目标预算。导出GLB重新导入一次，逐项核对法线、材质槽和实际图像连接；石/木纹理不能只存在于制作脚本却在导出后消失。用下方检查脚本的`gltfNativeBounds`核对原生GLB轴向和预先写出的宽/深/檐口/屋脊容差（非零bounds不算通过）。屋檐伸出要有明确额外尺寸。记录各贴图编码字节；若共享图片仍使文件超预算，先检查误导出大PNG、重复图片、无效贴图连接，再选择合适分辨率/编码。不得仅凭Blender材质视窗宣称GLB相同。

运行 `python3 -X utf8 scripts/inspect_glb.py model.glb --out inspection.json` 检查文件/图元/贴图开销；另用glTF Validator检查格式。检查脚本不评审美术、不取代完整验证器。

## 场景同时用于游戏与视频时

世界保持明确米制尺度，不迁就未定角色大小。模板GLB与材质可共享；实时碰撞/分区数据和取景灯光各自独立。除了单体源文件，保留与最终装配表一致的场景Blend、可重复的机位和实际渲染设置；贴图打包或用可靠相对路径。关闭建筑不因此补无用室内，取景可见的侧背面、屋顶和街角则需完整。后期视频用途不自动授权当前制作长视频或增加付费渲染。

## 用真实画面检证 Skill

至少交一栋模型的街边观察距离、近墙、侧背面图；普通与灰模使用同一相机/光照。给出加载该GLB的预览页，展示实测总tris、unique几何/材质/纹理数。用同一缓存源重复放置几栋，只验证复用和视觉尺度，不将此称为新街区。

加载记录分别写传输字节、fetch耗时、解析/图片解码就绪时间、首帧CPU提交时间；有GPU fence时可单列GPU完成等待。不把localhost缓存命中、CPU提交或文件缩小当公网秒开/FPS证明。格式与图像通过后再谈压缩与按区加载；KTX2/Meshopt只在加载器已接通并实际看过时采用。

老城隍庙周边店屋的小批施工，读取 [方浜店屋小段方法](references/fangbang-shopfront-slice.md)，复用已看过的轮廓、开口与材质契约，并变化不同商铺的开间、檐高和窗型。通用街屋脚本仍可参考 [已施工街屋示例](references/street-house-example.md)。在新目录派生，不覆盖基准。

实际浏览器图与离线渲染分开标。浏览器连接同类失败两次后先诊断/换低成本证据，不反复刷新大场景；未取得的运行证据保留为未验证。每轮最多优先修三条主要视觉/结构问题，主控自己看图，不额外安排审美review代理。

用户要求的单样板授权可直接做建模、导出与可逆验证；不扩大到付费生成、整城量产、角色/规则改动或自动任务。Skill测试结果见 [验证记录](references/verification.md)，不要把小样PASS当全城性能或用户美术采用。
