# 官方工作流的项目适配

状态：方法已吸收，新增优化／材质台／建模工作台试验尚未实施。这里不把官方案例当作Pawborough的性能或美术验收。主线仍为本地Blender可编辑源 → glTF运行资产 → 实际加载与同机位检查。

## 1. 从Game Studio吸收资产发布流程

官方Skill以DCC清理、GLB/glTF输出、glTF Transform整理、原点/变换/材质预算及碰撞/LOD作为资产流程。我们的已有GLB校验继续保留；工具选型不要求重建已通过的建筑。

### N4执行方法：一个已完成样板，逐层比较

1. 冻结一份能正确加载的原始GLB、源Blend、资产ID、材质ID及相机/光照，记录文件和图像哈希。先统计几何、嵌入图片、重复材料各占多少。
2. 单独做无损整理：剪除确实未使用资源、去重和重新打包。使用已安装的glTF Transform或在任务本地准备经来源核实的工具。命令按实际版本记录，不凭空填参数。
3. 对整理版再次检查稳定节点名、原点、世界变换、包围盒、真实门洞、纹理/切线与碰撞关联。不能为压缩而丢掉实例ID、安装锚点或交互层级；无损整理也可能影响这些语义。
4. 再分别测试几何压缩和纹理压缩。Meshopt可作为候选；Draco只在实际兼容与解码成本合适时选，不默认同时叠两种。KTX2/BasisU先接对应加载器/转码器；生产客户端与测试必须走同一加载路径。
5. 如果试简化几何，另存有损候选。保留近景门套、窗沿、檐口和开口；用相同相机判断剪影/阴影变化，不能只看三角数或Validator。
6. 输出一张对照表：原始、无损整理、几何压缩、纹理压缩/组合的实际字节、唯一图片/材质数、fetch/解析/解码时长、视图、失败原因。标明localhost/缓存/设备条件；文件缩小不直接称FPS提升。

原版始终可回退。仅技术检查通过的候选可继续作为实验输入，主控看图/机主采用另记。小于1MB不是必须牺牲可见质量的门槛；没有收益就保留原格式并进入下一就绪项。

## 2. 从Material Lab吸收材质诊断方法

官方案例把材料、照明和观察角度做成可直接调整的对象，并对不同材料提供不同控制。Pawborough适配为砖、瓦、木、石四类材质的轻量对照模式，优先复用现有预览页，不另造一个大型编辑器。

- 测试对象选已有“砖墙＋窗框＋墙脚＋小段屋檐”的建筑样板；球体可补看高光，不能代替墙面真实UV尺度。
- 固定几何与相机，分别控制基础色、粗糙度、法线强度、纹理米制尺度；金属度只在确有金属构件时使用，不给砖木统一金属感。
- 对比原项目日景与一个中性照明预设。调灯时先固定材质，调材质时固定灯，不同时改两组变量；不得为了“更真实”擅自把认可的清爽色彩做脏。
- 保留PBR、灰模、基础色诊断模式；如果当前渲染器没有可用的纯基础色模式，应明确实现后再声称该检查成立。
- 每次保存材质参数、纹理哈希、相机、tone mapping/exposure、光源与环境参数。一次改变一个有明确目的的参数组，保留可恢复预设。
- 木纹横竖、砖缝尺寸、背阴层次与门沿高光分别看。不同材料使用其适合的表面参数，不把玻璃示例整套套给木石。

以上是主控已定的诊断设计，工具由ZCode施工；尚未得到Pawborough新增材质台的真实运行证据。它服务于已有N4样板试验，不变成N0/N1/N2的前置。

## 3. Modeling Studio作为可选验证支线

公开展示可确认：WebMCP用于观察场景、编辑几何和调整纹理，视窗可观察改动。公开页没有证明能输出本项目所需的GLB/Blend/UV/法线/层级；不能据此宣称已经获得一套专业建筑建模Skill。

若机主另行让我们试用，先核实工具清单与导出格式，用一个独立的门框或墙窗小样验证：尺度/原点、节点语义、UV/PBR、导回本地与浏览器一致性。不上传既有项目资产，不开付费生成，不切换主生产链。功能或交付格式不满足就记录限制，主线继续Blender。当前只保留这一探针设计，不自动开始该支线。
