# 从实际门洞与交付故障提炼的检查

适用于场景导出、相机预设和交付脚本的修改，不要求每栋小改都重跑整城。证据来自2026-09-13方浜91米街段主控复验；R1/R3实际画面已通过，R2收口仍应按真实产物核对，不能视为已全部修好。

## 门洞不只是黑门片

已证实的缺陷：转角门扇与砖裙外皮同在一个平面，砖裙和墙体又整条穿过门口，造成WebGL密集条纹。修复是把墙体拆为洞两侧与门楣、砖裙在洞口收头、门扇退入、框覆盖真实墙厚；楼板边缘收进墙内。只移动黑门片或关闭阴影会留下错误结构。

“闭门”可以是实心门扇，不要求室内；“可通门洞”则必须在渲染网格和碰撞上都没有残留封墙。替换构件以明确ID记录，避免旧件还在、新件叠上去。浮空检查用目标表面／安装法线和实际截面，不只看对象中心或大AABB。

## 机位数据必须被运行时忠实执行

原预览的maxPolarAngle=π×0.495将5个平视/仰视相机抬高，例如1.6m变成约2.35m。允许水平和仰视后，11机位实际位置恢复。每个预设应在controls.update之后读取位置、目标、镜头和渲染尺寸，与输入比较；不能用改相机JSON来适配错误限制。

自动测试须经过实际运行时使用的初始化函数／配置，不另外在测试里硬写一个正确常量。保留一个平视或仰视负例即可抓住这个回归；不为每个镜头复制同一套实现断言。

## 真实导出与故障退出

- 校验对象是当前预览真实加载的最终GLB和对应kit／变更模块，不是更早的中间street.glb。输入有效且哈希没变的旧模块可复用PASS。
- glTF Validator报告的severity 0/1/2为error/warning/info。error或解析异常必须让被调用进程非零退出；只打印fail总数不能让shell的set -e阻止交付。
- manifest由本轮真实文件写入字节数、SHA和实例三角数，随后workspace与dist逐项核对。不要事后人工改哈希，更不能重导出后仍用旧图。
- 哈希负例先在完整独立沙箱验证正常版本exit0，再只损坏一个哈希，用同一个普通命令验证非零且错误确实由该哈希产生。存在missing file的沙箱失败不能证明哈希检测有效。坏GLB同理。
- 每次测试创建新沙箱，保留旧证据；不要默认删除目录。最终文件与负例副本必须隔离。
- 预览端口、默认启动命令、截图接口Origin应属于同一个任务。接口用已知任务Origin正例与无关Origin负例确认；不开放任意来源。HTTP fixture检查不冒充浏览器截图。
