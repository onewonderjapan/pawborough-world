# 全国寻味·毛绒上海小城：产品与美术规格

日期：2026-10-02。状态：**ready_for_model_switch / execution_not_started**。

机主确认上一轮明显改善，并要求整体美术升级、扩大小吃种类、全国各地小吃散落地图、开启图鉴。以下数量、章节与具体食物是主控为可交付首辑选择的实施建议；不是机主逐项指定，也不是已经制作完成的内容。

## 1. 成品与范围

首辑 24 味、8 章，每章 3 味；6→12→24 的每一批都能实际发现、拿取、品尝、保存和查图鉴。用“各地摊主来到上海小城参加寻味节”的轻设定解释食物分布。建筑仍保持上海街巷气质，避免把街区改成八种地区建筑的拼盘。

体验目标：进入后就看见一个清楚可达的摊位；吃第一口获得图鉴页；第二个目标引导短距离步行；自行车把玩家带到连接街区、池岸、园林入口等新地点。集齐章节获得手账印章，6/12/24 味分别获得封面贴纸、称号与完成页。奖励是既有界面的装饰反馈，不引入背包经济、付费、体力、随机掉落、重复刷取或每日限制。

本轮包含现有可探索区域的光照/材质/招牌/摊位生活感、灰猫的四类进食表现、食品资产、24 处可达取食点、图鉴与存档。本轮不扩地图边界、不制作可进入商场、不重建所有建筑；其他四只直立角色待本轮共享动作接口稳定后做 P2。已经明确不能进入的店面继续表现为封闭店面。

## 4. 四类拿取与吃法

| profile | 拿法 | 吃法与完成表现 |
|---|---|---|
| cupped | 双爪托住底部/两侧 | 抬向嘴边，咬一口有咬痕或食物体积变化；原三味维持已认可的大尺寸可读性 |
| wrapped | 一爪支承纸包，另一爪稳住食物 | 食物露出包装，嘴接触露出部分；纸包不穿脸、不一起被“吃掉” |
| skewer | 握签的合理位置，另一爪辅助 | 食物而不是木签接近嘴，少一颗/一块，签头远离眼睛 |
| bowl | 一爪托碗，另一爪按食物持小勺或筷子 | 汤/甜品用勺，面条/粉皮用筷子；工具带一口食物到嘴，碗保持稳定，内容减少；不把整只碗抬进嘴里 |

沿用完成一次品尝 3.2 秒作为默认节奏，阶段为准备→入口→回落；最终事件才入图鉴。暂停/刷新/取消不得凭空多记一次。站立时才开始品尝；拿食物骑车存入车篮，下车恢复，角色手不同时拿食物又握把。每味用表现参数描述抓握、入口与 bite 状态，不在 avatar.js 添加 24 组按 ID 分支。

M04 只补足四类动作所需的肩/肘/腕绑定与必要局部修形，保持脸、毛色、比例、车座/把手/踏板契约。先灰猫验收，不开展全身无限精修。若当前 12 骨无法自然持勺/持筷，制作版本化派生 rig，而不是把碗装食物伪装成面饼或减少范围。筷子作为一组受控工具加少量开合，不引入逐根物理模拟；`utensilKind=spoon|chopsticks` 是 bowl profile 的参数，不新增动作体系。

## 5. 全图布点与发现

建议 18 个现有摊位 +6 个新小摊车，每处首辑一种主打。现有摊位候选详见 JSON，原 stall-5/6/10 与原三味绑定保留。新增点的区域目标为：中心广场、方浜主街、方浜远端、池岸远侧、园林外入口连接处、城隍庙外商业连接处。禁止在殿内、桥面瓶颈、池水、屋顶、装饰台阶上布置取食点。

这些候选没有虚构坐标，也未全部通过到达验证。M00/M06 从 layout、道路和 Rapier 支撑面求出实际坐标，M12 再从正常入口按实际控制输入跑完全路线。各地食物可以分布在不同街区，章节不强求相邻；图鉴给“方浜街尽头附近”等地点提示。

- 发现条件：游玩模式、玩家有有效地面支撑、距顾客点 XZ ≤8m、垂直差 ≤2m、到顾客点上方 0.8m 的视线无遮挡。透明提示/蒸汽不挡视线，建筑墙体必须阻挡。每 foodId 只记一次发现。
- 取食继续使用 1.8m 距离、真实视线、有效站位与资源已就绪条件。所有候选顾客站位失败时该 vendor 不启用；修掉当前 `chooseReachable` 全失败仍保留目标的问题。
- 模型加载失败可显示“暂时准备中/重试”，不得给一个不可见食品入手或盖章。必需品种没有任何可用 vendor 时该批不能验收。
- 小地图：已发现显示食品标记，已品尝有图章；未发现只保留粗略街区探索提示，不一次性泄露全部精确坐标。当前跟踪点醒目，按 vendorId/foodId 查找，不按数组序号。
- 导航第一版使用地点文字、指南方向与标明“直线距离”的数值；无真实寻路时不伪造穿墙路线。道路路牌/色彩提示服务于转弯识别；自行车适合长段，窄路可停车步行。

路线设计目标：测试时正常玩家走完新手两味能理解循环；日常骑行 30–60 秒内有新的可见兴趣点；一章约 3–6 分钟、首辑约 20–40 分钟属于调优目标，M12 实测后记录真实值，不作为虚构承诺。禁止用坐标瞬移证据替代全路线实走。

## 6. 图鉴与轻任务

三态：`unseen` 显示剪影/章名/粗线索；`discovered` 解锁名称、地区风味、缩略图、地点提示；`tasted` 解锁盖章、简短口感文字和完成状态。拿取、靠近、在调试界面切状态均不能获得真实品尝。来源只写核实过的“常见于/代表风味”，不写未经核实的唯一发源地、老字号授权或疗效。

桌面 B 键及 HUD“图鉴”按钮打开手账。左侧章节与进度，中间食品卡，详情展示模型导出的静态图、食物名字/地区/短介绍、已发现位置与“设为目标”。有“全部/已发现/已品尝/未完成”筛选；24 项即可，不扩展复杂搜索系统。窄屏变单列且有返回按钮，360×800 和 1280×720 都不溢出；支持键盘焦点、可读字号、状态文字，不只靠颜色。

HUD 只显示当前一味目标、总计数与开图鉴入口，保留必要按键提示。6/12 批次以当前 edition 的必需 ID 集合计数，最终为 24；不要读取计划候选表当运行中的已上线食物。已经获得的 6/12 里程碑不因后续扩容丢失。

图鉴开启时冻结移动、骑行、吃食进度、非必要动效和世界摄像机；从骑行打开先安全停速但保留坐骑状态。关闭恢复先前暂停/游玩/骑行状态，清除按键积压，需要新输入才移动。Esc 优先关闭图鉴；如果原本是暂停或观察模式，不擅自恢复移动。帮助与图鉴共用 overlay 所有权和焦点恢复，防止重复暂停/恢复。暂停期间不能仍调用 OrbitControls 更新导致镜头跳到旧观察点。

收藏只存在本机浏览器；首次打开图鉴有一句说明。提供小型 JSON 导出/导入保存在设置抽屉：只导出收藏和里程碑，不导入位置/未知任意字段；最大 64 KiB，验证后集合合并，坏文件显示可读错误且不覆盖现状。本轮不做账号云同步。

## 8. 存档与恢复

新版 `pawborough.play.walk.v2`，schemaVersion=2；保留旧 key `pawborough.play.walk.v1` 作为迁移来源。新增 `catalogEdition`、`discovered`、`tasted`、`milestones`、`trackedFoodId`、`trackedVendorId`、`orphanedProgress`，保留 actor/feet/yaw/pitch/vehicle/heldItem/basketItem/eating 必需字段。集合序列化为去重 ID 数组，迁移结果包含 warnings。

读取顺序：合法 v2 → 没有合法 v2 时尝试合法 v1 → 两者都无效才用新档。v1 的 tasted 同时加入 discovered；手持/车篮食物也视为已发现；旧 goalIndex 按原三味顺序转 ID。旧三味全齐保存 legacy-three-tastes 里程碑，但不算完成新版 24 味。未知退役食品收藏放 orphanedProgress，不进入当前分母；当前手持未知物则安全清空并提示。

持久化先校验、写 v2、重新读回成功，再标记迁移成功，保留 v1 不删除。失败/配额不足不覆盖旧档，不把内存状态当保存成功。世界 sceneVersion 不兼容只重置位姿与车辆安全落点，收藏保留；正在吃饭的合法进度可恢复，不重复发完成奖励。

“新散步”只重置行程/位姿/手持，不清空图鉴；单独提供“清空图鉴并重新开始”，显示二次确认。刷新、开关图鉴、重复品尝、重复导入和重复迁移均幂等。收藏的增加只能经 discover/品尝完成/合法导入路径。

## 9. 加载、性能和发布闭包

- 启动只加载轻量元数据与出生附近所需模型，首批食品模型最多 3 种；不再用 `loadFoodCatalog` 一次拉取全部 24 模型。
- `acquire(foodId, ownerToken)` / `release(foodId, ownerToken)` 管理手持、车篮与摊位实例引用；同一模型并发请求去重。正常稳定时 resident 模型上限 8；最多 2 个并发下载，交接暂态上限 10。手持/车篮共享同一食品实例，周边展示最多 6 类；只淘汰无引用模型，允许超过限制时先卸载最远陈列再淘汰。
- 一个食品请求失败不能阻塞全目录；有有界重试按钮，异步返回使用 generation token，重置/离开后不能把旧对象加回新场景。共享几何/材质只在库所有者确认无引用时释放一次。
- 图鉴用静态缩略图，懒载页内图片，不开 24 个 WebGL 预览。装饰共享 geometry/material，沿用合批；夜间新增点光受现有光池预算管理。
- M00 在同设备、同浏览器、同视口、同路线采集基线。目标：p95 帧时 ≤基线的 1.2 倍，首载不下载全食品库，重复走两圈后资源计数趋于稳定；这不等于承诺某个跨机器 FPS。软件渲染只能证明逻辑，不能标记真实 GPU 性能通过。
- `tools/export_play_site.py` 从验证后的资产清单构建闭包，新增目录/图鉴/图片/摊车资源全部有 SHA；对外内容使用字段白名单，不混入本机路径、原始制作记录与私有凭证。没有引用的制作资产不上传。
- 发布继续不可变资源先传、入口最后更新；CSP 和域名/证书参数保留，回读入口与资产 SHA，保留上版回滚清单。旧 outbox 发布脚本的可复用安全部分迁入仓库工具后使用，不制造新永久隐式依赖。
