# 小吃摊碰撞与手持修复

反馈：走到小吃摊前会穿模，手上的小吃位置不对。ZCode 完成手持初稿；Codex 修补碰撞链、摊前铺面和动态蒙皮挂点，并直接验收。

## 原因与变化

摊位与可见街面之间缺少齐平的落脚铺面，脚下只剩低 0.42m 的世界底板；小胶囊从道路边缘落下时，Rapier 的校正还会穿入该底板。新增仅在游玩模式使用的局部摊前铺面，沿现有布局/朝向接续街面，同一尺寸生成显示与碰撞。柜台前额外留出真实猫头/爪的接触余量。控制器在原来的位移链内，用已登记的真实地面校核下一步脚点；没有每帧瞬移，也没有抬高显示模型。旧存档的地下落脚点不再恢复，试吃进度保留。

原手持偏移写死在上臂骨架上，与真实爪垫相差约 0.12m；原始胳膊的部分皮肤权重也绑定到躯干。手持与进食复用已验收的运行时手臂蒙皮修补，仅在需要时克隆几何，结束时恢复。选定真实爪垫的顶点后，持续采样其变形后的世界位置，把小吃 `socket_grip` 放在爪垫前 0.015m；采样点固定，避免抬臂后错误选到躯干顶点。食物维持 Y-up，持物手臂略抬起。暂停不更新动作，骑乘接管前归还手持克隆，下车重新标定；手、车篮之间仍使用同一个小吃实例。

灰猫、三味小吃、自行车与世界原 GLB 字节均未改动。封存 v1.0 标签保留。当前角色美术采用状态仍沿用其输入清单，不借技术测试自动改变其他角色的采用状态。
