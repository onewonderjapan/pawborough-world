# Pawborough 官方标准游玩路线 v1

目标：用一条可复现的逛吃路线体验灰猫、四类小吃、自行车、图鉴与旧存档恢复，并作为后续美术升级的共同验收基准。当前基线`9abe3ca4`（48味/34地区/48个售卖点），本地入口`http://127.0.0.1:5492/?play=1&at=center`。公开站仍是较旧版本，不作为本轮试玩目标。

标准路线不是新任务系统，也不改当前自动下一味顺序。玩家按下表的摊牌与路线走；已发现后可在图鉴/小地图设目标。完整路线规划行程约0.96km，含骑车短测与进食/观察；实际耗时必须由试玩记录，不以估算代替。

执行纪律：

- 第一站从正常中心入口开始；后续只走生产控制器，不中途传送，不直接写章，不改根骨/碰撞/时间步。白盒自动跟路只请求移动与视角输入，物理仍由原客户端校正。
- 试玩使用独立Chrome上下文，当前机主标签和进度不变。路线只允许读取状态，E/F/R/B/P/Space由实际键盘事件触发。
- 机器可读路线见`official-route.json`；完整变体`full`12站，操控分支`controls`9站。两路从同一基线独立开始，输出目录独立。
- 每站立即存JSONL状态和截图，再填写bug/美术观察，不能只跑全程后抄PASS。失败必须保留现场，区分游戏问题、跟路脚本问题和推测根因。
- 原单元/逐摊通过不能替代这条真实连续体验；这条路线也不冒充全部48味/全地图压力测试。

自动执行器：

```bash
node tools/playtest/standard-play-server.mjs --port 5971 --variant full --output /tmp/pb-official-review-a
```

浏览器准备后，`GET http://127.0.0.1:5971/status`读取下一站；`POST http://127.0.0.1:5971/step`执行一个检查点并返回截图/状态。试玩者应在站间查看PNG、即时写观察，再发下一次step。服务仅监听127.0.0.1，没有任意eval/传送/造章接口。结束用SIGTERM关闭独立浏览器。

问题记录最小字段：`id / checkpoint / severity / repro / expected / actual / feet / screenshot / confirmed-or-observed / suspectedCause`。美术建议最小字段：`observedImage / concreteChange / intendedPlayerBenefit / acceptanceShot / scope / dependency`。

脚本修正记录：新增摊车后先执行离线world.step并清空规划probeCache，再生成航点。首次实玩遇到两处规划受阻，属于脚本查询/缓存问题；失败现场保留，修正后安排复走。恢复玩法存档若被游戏校验回到安全出生点，执行器从S00重新跑路线、保留已获得收藏，不把出生点当作走完中途路段。

v1.1收尾变更：完整路线止于长街最后一摊，S11就地做收藏/重载/夜景，不强制无内容折返。旧v1返程在x50.37,z-20.45受阻2次，证据保留为待区分游戏/跟路原因的观察；不把删掉返程步骤标为该处游戏修复。存档恢复fixture只在独立上下文第一次种入，重载不会覆盖新章；boot等待使用可选链。

重建机器航点：`node tools/playtest/plan-standard-route.mjs`。只规划当前真实几何，不修改原地图。当前v1.1已经修正静态摊车query/cache生命周期，原失败报告仍保留。
