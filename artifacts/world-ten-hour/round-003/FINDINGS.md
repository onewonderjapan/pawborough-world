## 本轮两个主问题的结论

### ① post-gc 堆 ~4MB/h 缓升（round-2 遗留观察）→ 判定为有界增长，非泄漏

- **S4（default，主街+A/B，冷启动，62:01，`longrun/s4-mainAB-default-heap62/`）**：
  post-gc 堆 79.06 → 79.63MB，斜率 **+0.46MB/h；前半 +0.89 / 后半 +0.18MB/h（后半趋平）**。
  round-2 S1/S2 的 ~4MB/h 斜率在 ≥1h 尺度未复现为线性累积——35分钟跑看到的是爬升期，
  不是持续泄漏。资源计数全程恒定（几何/材质/纹理 496/476/346）、三角形 694430 精确锁定。
- **S5（allOn skins+props，A弄环线，冷启动，62:02，`longrun/s5-laneA-allon-heap62/`）**：
  post-gc 堆 81.30 → 81.75MB，斜率 **+0.32MB/h；前半 +0.65 / 后半 +0.12MB/h（后半趋平）**。
  与 S4 同判定：有界增长，非泄漏。资源计数恒定（648/563/518）、三角形 708066 精确锁定。
  本跑不注入失败恢复（round-2 S2 已证 6/6 恢复；注入重载会重置页面堆，污染斜率判定）。
- 判定依据：显式 `gc()` 后逐段平台的最小二乘斜率（round-2 引入的口径）+ 本轮前后半程拆分
  （斜率减半→有界；线性增长→可疑）。瞬时（gc前）峰值如实留档不作泄漏证据。

### ②帧时序的补充：allOn 与 default 的同口径对比（修正 round-2 的「数量级」说法）

- S4（default）全跑 p50=183ms / p99=667ms / mean 5.0fps；S5（allOn）p50=250ms / p99=600ms /
  mean 4.4fps——**同软件基线、同混合视图下 allOn 中位帧时间约 default 的 1.4 倍**，不是
  round-2 S1 vs S2 呈现的「16.7ms vs 500ms 差一个数量级」（那是轻视图行走段与重视图段的错配对比）。
- allOn 的重帧（>250ms 占 36%）仍触发 dt 钳制使行走呈半速慢放（S5 实走 426m/行走段≈0.5m/s）；
  default 在重视图段也会偶发触发。低配机的真实负担在重视图与加载时长，不在中位数。
- round-2 的「allOn ≈2fps」应更正为「p50 250ms≈4fps，重视图 1.5-2fps，轻视图可达 6fps」（S5 分段实测）。
  首页/README 的对应措辞已按此更新。
